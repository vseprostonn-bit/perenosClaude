# План: Фаза 0 - TG-бот с пейволом и реф-системой блогеров

Дата: 2026-08-24. Одна фича = этот план. Статусы фаз: `[ ]` / `[WIP]` / `[x]`.

**Цель фичи:** за 2-4 недели получить честные цифры воронки «регистрация -> образы -> оплата» и решить go/no-go. Метрики и пороги - в `ROADMAP.md` (Этап 1).

**Стек:** Python 3.12, aiogram 3 (бот, webhook-режим), FastAPI (вебхуки оплаты + страницы пейвола на Jinja2), PostgreSQL 16, SQLAlchemy 2, Alembic. Деплой - VPS (Coolify). Без Celery/Redis - хватает системного крона.

**Схема оплаты (решение 2026-08-24):** касса на своём домене, Robokassa (Робочеки - чеки без покупки ККТ), карта МИР + СБП, рекуррент. Telegram Stars не используем. Разбор - `docs/2026-08-24-oplata-v-tg-i-web.md`.

## Модель данных (ядро)

- `items` - товары: source (lamoda/wb/ozon/ym), external_id, title, category, color, price, sizes, photo_url, product_url, affiliate_url, in_stock, updated_at
- `outfits` - образы: slug, title, segment (повод/стиль), budget_tier, cover_photo, status, author
- `outfit_items` - слоты образа: outfit_id, item_id, slot (top/bottom/shoes/bag/accessory), alternatives (jsonb)
- `users` - tg_id, анкета (size, style, budget), ab_price_bucket, referrer_blogger_id, created_at
- `bloggers` - name, tg, promo_code, percent (15), rev_months (3-6)
- `subscriptions` - user_id, plan, price, paid_at, expires_at
- `payments` - inv_id (идемпотентность), user_id, amount, status, raw
- `referral_accruals` - blogger_id, payment_id, amount, status (pending/paid)
- `events` - user_id, name, payload, ts (вся воронка)

## Сбои и граничные случаи (продуманы до кода - не допущу сейчас)

1. **Аппрувы Admitad/Robokassa затягиваются** -> все заявки в день 1 (фаза A), код пишется параллельно; фолбэк каталога - вещи Lamoda по прямым ссылкам, партнёрские метки навешиваются после аппрува.
2. **Вебхук оплаты приходит дважды или фейковый** -> идемпотентность по InvId + проверка подписи; при сбое отвечаем ошибкой, Robokassa ретраит сама.
3. **Товар пропал из фида** -> in_stock=false, образ помечается «неполный», ежедневный отчёт о битых образах, замена руками (автозамена - не в фазе 0).
4. **Две реф-метки у одной пользовательницы** -> правило первого касания, фиксация при /start, перезапись запрещена.
5. **Одна девочка видит разные цены A/B** -> бакет детерминирован по tg_id; показанная на пейволе цена сохраняется и не меняется.
6. **Блогер накручивает самоподписки** -> первые выплаты только по ручному реестру, флаг совпадения blogger.tg == user.tg.
7. **Возврат платежа** -> ручная политика фазы 0: возврат по обращению, сторно начисления блогеру.
8. **Персональные данные (152-ФЗ)** -> анкета минимальна (размер/стиль/бюджет), политика ПД на странице, данные только на нашем сервере, в git не попадают.
9. **Домен или касса упали** -> крон-проверка пейвол-страницы каждые 10 мин, алерт владельцу в TG.
10. **Rate limits Telegram** -> рассылок в фазе 0 нет вообще, только ответы на действия - очередь не нужна.

- Celery/Redis - системный крон.
