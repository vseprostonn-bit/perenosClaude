# Контрольный набор для матчинга

100-150 реальных фото луков с ручной разметкой правильных ответов. Это линейка:
по ней меряется любое изменение в распознавании и поиске. Без неё «стало лучше» -
ощущение, а не факт.

Лежит здесь, а не в `data/`, потому что `data/` по правилам проекта в гит не
попадает, а набор нужен обоим партнёрам.

## Что кладём

Пары файлов с одинаковым именем:

```
001.jpg     фото лука - скрин из соцсети, кадр с улицы, витрина, примерочная
001.json    разметка
```

Фото берём разные специально: хорошее студийное и кривое с телефона, полный
рост и по пояс, один человек и двое, зима и лето. Набор, собранный из одних
красивых кадров, врёт.

## Формат разметки

```json
{
  "gender": "women",
  "note": "скрин из соцсети, вечерний свет",
  "items": [
    { "slot": "outerwear", "exact": [12345], "acceptable": [12388, 15002] },
    { "slot": "bottom",    "exact": [],      "acceptable": [23001, 23044] },
    { "slot": "shoes",     "exact": [],      "acceptable": [] }
  ]
}
```

- `slot` - категория из тех же значений, что и в разборе: `top`, `bottom`,
  `dress`, `outerwear`, `shoes`, `bag`, `accessory`.
- `exact` - id той же самой вещи в нашем каталоге. Бывает редко.
- `acceptable` - вещи, которые пользовательница засчитает как «то самое»:
  тот же тип, тот же цвет, тот же силуэт, та же длина. Обычно 2-5 штук.
- **Пустые оба списка** - в каталоге такого нет. Это не брак разметки, а важный
  случай: правильный ответ системы здесь - честно сказать «точного нет».

Поле `look` появится само после прогона с `--stage full` - это кэш разбора,
руками его писать не нужно.

## Набор собирается в два захода

Каталог живёт в базе на сервере, поэтому подбор кандидатов работает только там.
Но фото можно собирать откуда угодно и когда угодно:

```bash
# на ноутбуке, без ИИ и без каталога - просто складываем фото в набор
.venv/bin/python -m scripts.annotate_golden add ~/Downloads/look1.jpg --no-scan
```

Когда каталог доступен, одна команда дозаполняет все такие записи - разбирает
фото и подбирает кандидатов:

```bash
.venv/bin/python -m scripts.annotate_golden enrich
```

Уже проставленная руками разметка при этом сохраняется: она дороже разбора.

## Быстрый путь: помощник разметки

Руками искать вещи в базе не нужно, это делает скрипт:

```bash
.venv/bin/python -m scripts.annotate_golden add ~/Downloads/look.jpg
```

Он кладёт фото в набор под следующим номером, разбирает его, ищет по каждой
вещи кандидатов и пишет их в json в поле `suggestions` - с id, названием,
ценой и ссылкой на фото.

```bash
.venv/bin/python -m scripts.annotate_golden html
```

Собирает `eval/golden/preview.html`: фото лука и кандидаты картинками рядом.
Открываешь в браузере, смотришь глазами, выписываешь нужные id и переносишь их
в `exact` или `acceptable` в json. Уже размеченное подсвечено рамкой.

```bash
.venv/bin/python -m scripts.annotate_golden check
```

Проверяет набор: нет ли битых id, неизвестных слотов, фото без разметки.
Гонять перед каждым замером.

## Как искать id вещей для разметки (руками, если нужно)

```sql
-- по типу и цвету
select id, title, color, price from items
where category='outerwear' and color='бежевый' and in_stock=1 limit 40;
```

Смотрим фото по `photo_url`, выбираем подходящие, выписываем id.

## Как мерить

```bash
.venv/bin/python -m scripts.eval_matching                      # только поиск, без затрат
.venv/bin/python -m scripts.eval_matching --stage full         # ещё и разбор фото
.venv/bin/python -m scripts.eval_matching --note "новый реранк" # с пометкой в лог
```

Результат каждого прогона пишем строкой в `docs/matching-log.md`.

## Правило пополнения

Каждый случай, когда пользовательница нажала «не то», попадает сюда с правильным
ответом. Набор растёт сам, и система перестаёт повторять старые ошибки.

## Состояние набора (09.09.2026)

192 фотографии собраны и лежат в этой папке: `001.jpg` … `192.jpg` плюс json
рядом с каждой. Источник - выгрузки модных телеграм-каналов, отобраны вручную
через `scripts/pick_golden.py`. Используются только внутри, для замера
точности: это контрольный набор, а не контент для публикации.

Json пока пустые скелеты - фото добавлены без разбора и без каталога
(`add --no-scan`), потому что базы на машине Саши нет.

**Следующий шаг - на сервере, где есть каталог:**

```bash
cd ~/obraz-app && .venv/bin/python -m scripts.annotate_golden enrich
```

`enrich` пройдёт по всем записям, разберёт фото через vision и подставит
кандидатов по каждой вещи. После этого `html` собирает превью, человек
переносит id правильных вещей в `exact` и `acceptable`, а `check` проверяет
набор на битые id и пустые слоты.
